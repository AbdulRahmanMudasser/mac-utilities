# Speech Transcription Conventions

## 1. Purpose And Ownership

This guide owns shared design and engineering rules for local speech transcription. Delivery status and incomplete verification belong in the desktop execution workflow and phase record.

`TranscribeFeatureController` owns presentation and setup actions. `TranscriptionSessionCoordinator` owns the recording generation, language lock, capture lifecycle and successful-history decision. Platform speech adapters own microphone capture, model integrity and native inference. Views present controller state and never own capture or model leases. Task handles exist for cancellation, joining and duplicate-action guards; observable setup/session state is the source for readiness and input locks. Clear task ownership before publishing terminal setup state so model readiness and action availability cannot diverge.

## 2. Language And Assets

The user explicitly selects English or Urdu; English is the initial choice and later choices persist. Each language uses its pinned q5 model and explicit language code. Do not detect a language or substitute a model. Readiness belongs to the selected language and its verified model; setup for one language must never make the other language appear ready. Model files are app-local, verified against pinned size and SHA-256 before atomic publication, and never stored in Git or the usage App Group. A model in use retains a lease until inference and cancellation have completed.

English and the speech detector are acquired during explicit setup. Changing the language automatically starts setup for the selected language; do not require a second setup action. Urdu access is gated: each user must request and receive their own authorization, download the authorized file under the publisher's terms, then select it for verification and import. Do not imply that access is preapproved or provisioned for new users. Never embed, collect or log account credentials. Cancelled selection returns to setup without marking the model ready.

## 3. Recording And History

Request microphone permission only for a user-initiated recording. Lock language selection during setup and recording. Recording continues when the utility window closes. Stop drains accepted capture and inference before saving; cancellation, failures and stale generations cannot publish history. Audio remains transient in memory and is never written as an audio file. History retains only complete, nonempty transcripts with stable identity and the time saved. Store it as local JSON in app-sandbox Application Support, separate from the usage ledger, with a `0700` history directory and `0600` file; reject symbolic links and publish updates atomically. The app does not separately encrypt the JSON. Retain entries until the user deletes them, with no automatic expiration. Do not log audio or transcript content. Once the selected model is ready, a History storage error alone does not block recording; a transcript whose save fails remains visible as a transcript and is never presented as a saved History entry. Show the newest saved entry first and use whitespace to distinguish entries without separator lines. Copy and Delete act on one entry; Delete does not ask for confirmation. Put Clear History inline with the History heading, disable it when History is empty or unavailable, and confirm before permanently deleting all saved entries.

Capture callbacks use preallocated bounded buffers and do not wait for inference. Clear copied microphone samples before a buffer slot is reused. Bound input callbacks by duration and storage; convert accepted audio to 16 kHz mono on one sample timeline. Bound each capture chunk to one second, pending audio to ten seconds and each Whisper window to thirty seconds; infer every two seconds and retain two seconds of lookahead before finalizing speech. Advance the next window from the last finalized boundary without reusing committed samples. Do not silently drop audio: report capture-size, continuity, backlog, window-limit, VAD and timing failures.

Model segments use half-open sample ranges. Convert the pinned whisper.cpp centisecond timestamps to the original sample timeline, clamp its permitted short endpoint extension to samples actually captured, and reject malformed or non-monotonic results. Merge overlapping segments from one result while preserving their text; across rolling windows, skip segments fully covered by finalized audio and fail on partial overlap. Deduplicate only exact range-and-text matches. A normal stop drains accepted capture and recognizes the final tail; cancellation invalidates the generation before cleanup and never saves partial text.

## 4. Presentation And Verification

Use the shared capability card as the single visible surface for model readiness, microphone permission, recording availability and current errors, with actionable recovery in the same card. Derive the card's title, severity, recovery actions and Start Recording availability from one coherent capability presentation; every capability state must set Start availability explicitly. Use a specific Title Case title for the failure domain, such as audio capture, speech inference, model setup, History or copying; do not label every operation failure `Transcription Error`. Keep an accurate, concise sentence-case detail from the underlying error without inventing causes or discarding useful failure information. Include only current blockers and actionable explanations: do not append granted or unrequested microphone status to model-readiness messages. When multiple prerequisites or independent errors are current, keep each cause and its recovery action represented in the same card; prioritizing one issue must not silently hide another. Keep the separate permission row absent, and make the accessibility value describe the same relevant capability state without unconditionally repeating permission status.

In the live app, show a ready state only when the selected language's verified model and runtime can start; microphone permission may be requested after the user starts recording. Show an accessible progress indicator in that card while model setup, permission requests, inference preparation, finalization or stopping is in progress. Interactive previews may simulate capture and inference but must identify simulated readiness and permission clearly; their Start and Stop actions must work through injected fake dependencies and produce clearly synthetic, language-appropriate text without touching the microphone or model assets. Use a native language dropdown and the Usage History empty-state styling. History rows use shared timestamps and accessible icon-only Copy and Delete actions. Keep the transcript accessible as child text and do not repeat its full contents in a row-level accessibility value. Preserve the existing sidebar shortcuts and support keyboard and VoiceOver interaction.

Present the cumulative confirmed transcript as the main text in one Transcript card. Do not add visible `Final` or `Partial` labels. Keep transcript text leading aligned. When unconfirmed partial text exists, continue it below the confirmed text in that same card with a subtle waveform icon beside the live text, vertically centered against the live text block, and secondary text styling. Apply the shared Urdu baseline adjustment so its glyphs appear optically centered beside the waveform. Use spacing instead of a divider or nested card. Expose the confirmed and live text with distinct VoiceOver labels, and do not announce every partial update.

Automated tests use isolated preferences, model stores and history and must not request real microphone permission. Verify signed native capture, model loading, long pauses, English and Urdu accuracy, latency, resource use and accessible layouts on the target Mac before claiming release readiness. Debug preview routes and synthetic fixtures must be absent from Release. Do not include private audio or transcript content in logs.

## 5. Native Runtime

The build script pins whisper.cpp and builds an arm64 framework with embedded Metal. Keep one serialized Whisper/VAD context alive through native work and cancellation; do not release context or sample storage until the synchronous native call returns. The pinned VAD API has no abort callback, so check cancellation before and after its bounded thirty-second pass. In the pinned runtime, `whisper_full` status `-1` means its internal VAD pass failed and must remain distinct from decoder errors. A missing VAD segment result is failure; only a successful zero-segment result means silence. The small local VAD patch propagates graph-compute failure rather than accepting incomplete probabilities as silence; remove it only after an equivalent upstream fix is pinned and verified. Keep the patch minimal and validate it against the pinned source on each rebuild.
